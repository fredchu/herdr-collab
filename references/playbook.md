# herdr 多 session 協作——方法論與失效模式（通用版）

> 2026-08 一次 dispatch 基礎設施大修中定型：兩個 peer session 對抗協作，
> 八個回歸斷言五個來自對方的對抗掃描、互抓 blocker 級 bug 各一、方法層錯誤各一。
> 同一役也產生了協作特有的最大錯誤（見失效模式一），修法已內建進 SKILL.md 的意圖 gate。

## 為什麼 peer 而不是 subagent

subagent 繼承派工者的 prompt 與 frame——它可以幫你做事，但無法質疑你問題問錯了。
peer session 沒有共享錨定：它重跑你的統計時用自己的口徑、讀原始資料時不帶你的先驗。
「驗證不自驗」只有在驗證者獨立於產出者時才是真的。

## 價值的真實來源（缺一個就退化成貴的聊天）

1. **換口徑重做**：複驗＝用不同的查詢/定義/工具把對方的結論重新推導一次，
   數字對上才算複現。只讀對方結論說「合理」是假對抗。
2. **ground truth 裁決**：分歧不靠說服，靠 log／語料／測試。沒有可裁決證據的任務
   （純品味、純探索）不適用這個模式。
3. **挑錯授權**：briefing 明寫「你的判斷若跟我衝突直接講，不要遷就」。
   沒有這句，兩個 agent 會禮貌地互相同意。

## 失效模式（每一條都真實發生過）

1. **共識≠用戶意圖**。互審提高事實正確性，同時給越權製造虛假正當性：兩顆腦交叉驗證
   到高置信度後，容易把「我們的共識」誤當「決策授權」。實例：一次實驗數據充分的
   預設變更被雙方互審通過後落地，事後發現用戶要的從來不是那個方向，且實驗本身有
   混淆變數。修法：意圖 gate 清單——改變日常行為的決策無論共識多強一律回用戶。
2. **並行同因誤判**。把對方 session 的狀態用自己的情境解釋，解釋自洽就停止取證
   （例：把對方 worker 的改動讀成自己的 worker 越界）。修法：跨 session 狀態只從
   共同事實檔讀（執行紀錄、findings 檔），不從 worktree 現況推論。
3. **共用資源撞筆**。同一使用者的多個 session 常共用交接檔／memory／知識庫，
   多人寫＝後寫覆蓋先寫。修法：收尾一支筆（context 最低者執行）。
4. **假對抗**。見上；訊號是複驗方沒有產生任何新查詢/新數據就同意了。
5. **「是不是我造成的」基線選錯**。多 commit 快速迭代下，判斷紅燈是否 pre-existing
   時基線必須早於自己的**全部**改動——拿自己中間的 commit 當基線，可能正好選中肇事者。
   機械做法：`git worktree add <tmp> <首個自己改動>^` 重跑測試 diff 失敗集合。
6. **沒消息當死掉**。09-10 曾有 pi 額度用完後閒置，既沒人處置，也沒人用正面證據判定
   它是否已死。沉默只能算未知；應按 SKILL.md §3.5 盤點狀態、pane 與 workspace，再決定處置。

## 成本模型

- 訊息開銷約佔總 token 15-20%（長內容落檔、訊息只帶結論的紀律下）
- 2 個 session＝1 條通道；3 個＝3 條；4 個＝6 條（平方成長，故上限 3）
- 值回票價的條件：任務的錯誤成本 > 協調成本。infra 預設、事故調查、
  會被很多人依賴的產出——值得；例行修檔——不值得。
